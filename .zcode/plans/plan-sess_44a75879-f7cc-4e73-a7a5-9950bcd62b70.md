# 实现「AI 创建世界」会话交互

## 问题根因

`handleOpenWorkbenchAgentSession`（`App.tsx`）对 dialog 会话：

1. **已有 surface** → 只回焦，不发 `initialMessage`
2. **localStorage 有绑定 session** → resume，也不发 `initialMessage`
3. 绑定只检查 session **是否存在**，不检查是否为空/失败

因此：首次失败、空会话、或二次点击恢复空窗时，会出现「窗口出来了但没发起对话」。

## 目标行为

| 场景 | 行为 |
|---|---|
| 无会话 / 绑定失效 | 新建 + 自动发送开场 |
| 绑定会话为空/无有效回合 | 清绑定，新建 + 自动开场 |
| 有历史且空闲 | 恢复/回焦，不重发开场 |
| 运行中再次点击 | 回焦 + toast，不打断、不新建 |
| 用户点「重新开始」 | 确认后清绑定、关旧 surface、新建 + 自动开场 |

默认仍复用固定 `conversationKey`（`novel.world.architecture` / `template-config`），不每次硬开新会话。

## 实现方案

### 1. Host 会话决策（核心）

文件：`src/renderer/App.tsx` → `handleOpenWorkbenchAgentSession`

抽出可单测纯函数到：

- `src/renderer/workbench-host/workbenchAgentSessionPolicy.ts`

```ts
isEmptyOrBrokenSession(meta): boolean
// turnCount 缺失/0 且无 lastMessagePreview → 视为空，应重建
```

改写 dialog 分支决策顺序：

1. **forceNew / restart**（见下）→ 清 binding、关闭同 key surface → 走新建
2. **live surface 存在**
   - `isGenerating` → focus dialog + `toast.info("…进行中，已为你打开")` → return
   - session 空/坏 → 关 surface + 清 binding → fallthrough 新建
   - 否则 focus + 可选 toast「已回到上次会话」→ return
3. **binding 存在**
   - `getSessions` 找不到 → 清 binding
   - 找到但 empty/broken → 清 binding
   - 健康 → `resumeSession`（仍不带 initialMessage）
4. **否则** 新建 + `initialMessage` 自动发送（现有路径）

Focus 复用现有 setTabs 把目标设为 `dialog`、其它 surface 设为 `dock`、`setActiveTabId(sourceTabId)`。

### 2. Surface 上的「重新开始」

文件：

- `src/renderer/workbench-host/WorkbenchAgentSurfaceHost.tsx`
- `src/renderer/types/tab.ts`（surface 状态）
- `src/renderer/App.tsx`（handler）

做法：

1. 创建 surface 时在 `workbenchAgentSurface` 上保存重启快照（最小集）：
   - `title`
   - `initialMessage`（开场全文）
   - `promptId?`
   - `toolset?`
   - 已有 `conversationKey` / workspace / workbenchId
2. 标题栏增加「重新开始」按钮
3. 使用现有 `ConfirmDialog`（z-300，盖过 dialog z-210）确认
4. `onRestart(tabId)`：
   - 清 `agentConversationBinding`
   - 关闭该 surface tab
   - 用快照再次走 open 路径（等价 forceNew + 原 initialMessage）
5. 运行中点「重新开始」：确认文案说明会结束当前生成；确认后同样重建

不把「重新开始」做进 novel 工作台内部，符合 workbench 边界（host 拥有会话生命周期）。

### 3. 合同扩展（小）

文件：`src/shared/workbench-sdk/contracts.ts`

```ts
/** 强制新开任务会话，忽略 conversationKey 绑定与现有 surface */
readonly forceNew?: boolean;
```

Host open 识别该字段；novel 主按钮默认不传。Surface 重启走 host 内部 force 路径即可，不必 novel 再调一次。

### 4. Novel 侧（尽量不动）

`renderer.tsx` 的 `launchWorldAgent` 保持现有 payload（固定 conversationKey + dialog）。

可选小改进（若实现成本低）：

- 启动中防抖已有；错误仍用 `operationError`
- 不在 novel 内显示运行状态（host surface 已有「正在运行」）

### 5. 反馈文案

用 `toastRef.current.info/warning`：

- 运行中回焦：`世界架构对话进行中，已为你打开`
- 恢复历史：`已回到上次的世界架构对话`
- 空会话自愈：可不 toast，直接开聊；或 `上次会话未启动成功，已重新开始`
- 重新开始成功：靠新窗 + auto-send，不必额外成功 toast

### 6. 测试

| 文件 | 覆盖 |
|---|---|
| `workbenchAgentSessionPolicy.test.ts` | empty/broken 判定 |
| `App.helperLaunch.test.tsx` | dialog 二次打开回焦；空绑定重建并发 initialMessage；运行中不新建；forceNew/restart 清绑定 |
| `renderer.test.tsx` | 断言现有 `conversationKey` / `presentation: "dialog"`（防回归） |

测试手段：沿用 helper launch mock（`OPEN_WORKBENCH` + `onOpenAgentSession`），扩展 mock `getSessions` / tabs `isGenerating`。

## 验证

1. 冷启动点「AI 创建世界」→ 弹窗 + 自动发出开场并开始生成
2. 生成中再点 → 只回焦，不新开、不重发
3. 最小化后再点 → 恢复同一会话
4. 人为制造空绑定/空 session 后再点 → 自动重建并开聊
5. 点「重新开始」确认 → 新会话 + 新开场
6. 跑相关 unit/dom 测试
