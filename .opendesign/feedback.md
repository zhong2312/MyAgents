# v2 设计评审与 v3 修改要求

## P0：作用域模型过于复杂

- 现状证据：v2 同时展示空间锚点、制度作用域、多选范围、继承方式、冲突优先级和冲突审查。
- 问题：用户容易理解成“每种设定都要与每个空间层级组合”，形成设定与空间的笛卡尔积。
- 期望：删除双轴作用域，把所有设定直接归属于一个空间节点。
- 阻塞：是。

## P0：缺少可配置的层级类型元模型

- 现状证据：v2 的空间层级虽然可展开，但层级名称和结构主要是原型数据，没有展示每个节点必选层级类型。
- 期望：每个节点必须关联 `LevelType`；空间树可以任意组织；层级类型本身可配置。
- 阻塞：是。

## P0：缺少可配置的默认设定模板

- 现状证据：v2 左栏仍以固定的设定类目和节点组织内容。
- 期望：引入 `SettingTemplate` 与 `LevelTypeSettingProfile`。层级类型决定默认显示的模板，但不禁止作者添加其他设定。
- 阻塞：是。

## P1：需要完整元配置管理体验

- 期望：提供“层级类型 / 设定模板 / 类型模板关联”三个元配置页面，并演示配置变化如何影响空间节点设定列表。
- 阻塞：是。

## P1：主编辑界面需要收敛

- 期望：改为“空间树 / 当前节点设定 / 页面级 Markdown 编辑器”三栏；去掉四视图 Tab、作用域摘要和冲突横幅。
- 阻塞：是。

## P1：配置变化必须非破坏

- 期望：更换节点类型、移除模板关联、更新模板版本时明确展示保留策略，不删除或覆盖已填写正文。
- 阻塞：是。

## P2：保留 v2 的视觉优点

- 保留暖纸配色、收起的工作台导航、紧凑工具栏、中文内容和整页编辑工作面。
- 不保留双轴作用域及其视觉强调。
