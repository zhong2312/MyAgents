# 小说物品库 v1 设计任务书

## 目标

为 MyAgents 小说工作台设计独立一级模块“物品库”，覆盖物品分类管理、物品浏览与编辑、自定义字段配置，以及分类或字段变化时的数据保留策略。

本轮只产出可点击设计原型，不修改 MyAgents 产品源码。必须生成新的 `item-library-v1/`，保留现有 `setting-library-v2/`、`setting-library-v3/` 及其预览文件不变。

## 产品定位

物品库服务于高频创作管理，不是展示型图库。作者需要快速完成以下工作：

1. 用分类树组织兵器、法宝、药剂、关键道具、货币等物品。
2. 在同一工作面搜索、筛选、比较和编辑物品。
3. 让分类定义可复用字段，让同类物品保持一致结构。
4. 为某一件特殊物品追加仅它拥有的字段。
5. 修改分类或字段方案时保留已经填写的资料，不静默丢失内容。

物品库在小说工作台左侧导航中是独立一级入口，建议路由为 `items`，图标使用 `package-open`。不得隐藏在设定库、知识库或世界地图内部。

## 核心模型

```text
ItemCategory 分类树
├─ 每个分类拥有稳定 categoryId
├─ 子分类继承全部祖先分类字段
└─ 分类可定义有序 FieldDefinition
   ├─ fieldId 是稳定身份，字段名称不是身份
   └─ 字段作用于当前分类及其后代

Item 物品
├─ 必须属于一个主分类；保留“未分类”作为安全归宿
├─ 具有不可删除的基础字段
├─ values[fieldId] 保存分类字段值
├─ itemFields / values 保存仅此物品的扩展字段
└─ descriptionPath 指向独立 Markdown 正文
```

同一物品只选择一个主分类，跨维度检索使用标签，避免多个分类字段方案发生歧义。

## 预设基础字段

所有物品固定具备以下基础字段，不能被分类字段覆盖或删除：

- 名称：必填。
- 别名：多个短文本。
- 主分类：必填，可暂存到“未分类”。
- 状态：构思中、已登场、遗失、损毁、归档。
- 标签：跨分类检索用。
- 一句话摘要：用于列表预览和 Agent 检索摘要。
- 封面/参考图：保存项目内 `assets/` 相对路径，不把二进制写入 JSON。
- 稳定 ID、创建时间、更新时间：系统元数据，在详情的弱化信息区展示。
- 详细描述：独立 Markdown 正文，不作为自定义长文本字段的替代品。

## 自定义字段

字段类型至少覆盖：

- 单行文本；
- 多行文本；
- 数字，可配置单位；
- 单选；
- 多选；
- 开关；
- 日期/故事时间文本；
- 实体引用，可限制为人物、势力、地点或其它物品；
- 图片/附件引用，只保存项目内相对路径。

字段定义可配置名称、说明、分组、类型、是否必填、默认值、选项、单位和排序。

在物品编辑页新增字段时必须先选择作用域：

- “应用到当前分类”：默认选项，字段进入当前分类方案，对该分类及后代物品可见。
- “仅此物品”：只为当前物品创建扩展字段。

继承字段在子分类中显示来源。子分类可以调整继承字段在当前界面的分组和排序，但不能改变已有数据字段的类型或稳定 ID。

## 非破坏规则

- 移动物品到其它分类时，先展示变化摘要：新增哪些字段、哪些旧字段不再适用。旧值转入“保留字段”，不删除。
- 归档字段时，字段从新物品表单隐藏；已有值继续在“保留字段”中只读展示，可恢复字段。
- 已有数据的字段类型不可直接修改；需要复制为新字段并显式迁移。
- 删除分类前必须处理子分类和物品。非空分类只能归档，或先把内容移动到其它分类。
- 重命名字段只改显示名称，`fieldId` 和已有值保持不变。
- 修改默认值只影响之后创建或尚未填写该字段的物品，不覆盖已有值。

## 持久化建议

延续小说项目 Git 友好的 Markdown + JSON 模型：

```text
world/items/
├─ meta.json                 # 分类树、字段定义、字段继承与归档状态
├─ index.json                # 物品摘要、排序与 record/page 路径索引
├─ records/<item-id>.json    # 基础字段、自定义字段值、系统元数据
└─ pages/<item-id>.md        # 连续阅读的详细描述
```

所有 JSON 使用 `schemaVersion: 1`、UTF-8、2 空格缩进和 `/` 相对路径。写入必须复用 `WorkbenchStorage` 与 `expectedContent` 冲突检测。新增物品时先创建 record 与 Markdown，再登记 index；索引失败时回滚新文件。旧项目只有 `world/items/index.json` 时允许内存归一化，未经显式迁移不得静默重写。

## 主物品库界面

桌面主视口 1440×900，延续工作台默认收起的一级导航。内容区采用连续三栏工作面，不使用卡片套卡片：

1. 左栏“物品分类”：约 224px，分类树持续显示物品数量；包含“全部物品”“未分类”“已归档”和用户分类。支持折叠、拖动排序、右键新增子分类/重命名/归档。
2. 中栏“物品列表”：约 340px，顶部搜索、状态/标签筛选、排序和列表/紧凑网格视图切换；行内显示名称、分类、摘要、状态和更新时间。
3. 右栏“物品详情”：占满剩余宽度。顶部显示名称、分类路径、状态、保存状态与更多菜单；正文使用“资料 / 描述”页签。

“资料”页签使用不套卡片的分组表单：基础信息、分类字段、仅此物品字段、保留字段。长表单分组可折叠，基础信息默认展开。字段标签旁显示来源分类；必填、帮助说明和单位紧贴对应控件。

“描述”页签复用设定库的页面级可视化 Markdown 编辑器，占满可用高度，提供常用格式工具、可视化/源码切换和保存状态。

主工具栏提供：

- 搜索输入；
- 筛选按钮；
- “分类与字段”入口；
- 带 `plus` 图标的“新建物品”主命令。

## 分类与字段管理界面

从主物品库进入同一工作台内的全屏配置工作面，并可返回原位置。采用三栏：

1. 左栏分类树：新增根分类、新增子分类、拖动排序、显示继承层级和物品数。
2. 中栏分类属性：名称、说明、图标、父分类、颜色标记、归档状态；显示移动或归档的影响摘要。
3. 右栏字段方案：按分组排列字段，持续显示字段类型、必填状态、来源分类、使用物品数；支持拖动排序、新建、复制、归档和恢复。

字段编辑使用独立弹窗或右侧抽屉，完整显示字段配置。选项型字段支持增删、排序和设置默认项。已有数据时类型控件锁定，并明确说明原因。

## 示例数据与必须演示的流程

项目名使用“烬海编年史”。分类树示例：

```text
兵器
├─ 长兵器
│  └─ 枪
└─ 短兵器
法宝
药剂
关键道具
货币
```

选中物品“烬潮枪”。基础信息包含别名“镇潮”“黑脊”，分类为“兵器 / 长兵器 / 枪”，状态为“已登场”。

分类字段示例：

- “兵器”定义：等阶、持有者、当前状态。
- “长兵器”定义：长度、重量。
- “枪”定义：枪材、枪纹、使用限制。
- “烬潮枪”拥有仅此物品字段：封印层数。

原型必须可以点击演示：

1. 在分类树和物品列表间切换，选中“烬潮枪”查看完整字段来源。
2. 新建物品并选择分类，表单立即出现继承字段。
3. 在物品页新增“封印层数”，选择“仅此物品”。
4. 新增“炼制流派”，选择“应用到枪分类”，返回列表后同类物品出现该字段。
5. 把物品移动到“法宝”，展示非破坏性变化摘要和保留字段。
6. 进入分类与字段管理，新增/排序/归档字段，并看到已有数据时的保护提示。

## 状态覆盖

必须覆盖并能在原型中观察到：

- 正常有数据状态；
- 首次使用空状态；
- 分类下无物品；
- 搜索/筛选无结果；
- 加载状态；
- 保存中、已保存、保存失败；
- 外部修改冲突，提供“载入磁盘版本”和“保留当前草稿”解释，不允许直接覆盖；
- 分类或字段已归档；
- 未保存时切换物品的确认；
- 长分类名、长字段名、长选项文案不溢出。

## 响应式

- 1440×900：完整三栏高频编辑。
- 1024×768：分类栏可收起，物品列表与详情保留分栏。
- 390×844：分类通过抽屉打开；列表与详情使用分步导航；详情编辑是独立工作面，顶部提供返回物品列表。弹窗改为底部面板或全屏表单。
- 所有视口不得横向溢出、文字遮挡或因动态状态改变固定工具栏尺寸。

## 视觉语言

- 延续 MyAgents 暖纸设计：`#faf6ee` 主背景、`#fffcf7` 抬升面、`#e8dccf` 下沉面、`#1c1612` 正文、`#6f6156` 弱文字、`#c26d3a` 暖强调、`#2e6f5e` 冷辅助。
- 正文 16px、常规 UI 14px、元信息 12px；不随视口宽度缩放字号，字间距为 0。
- 安静、密集、工作导向；不用营销式标题、装饰渐变、彩色光斑、大圆角或卡片堆叠。
- 图标使用 Lucide。图标按钮必须有 `title` 与 `aria-label`；列表、标签和表单优先使用熟悉控件。
- 卡片圆角不超过 8px；页面分区用边框和连续面，不把页面 Section 做成浮卡。

## 交付要求

- 生成 `item-library-v1/index.html` 作为主入口，可拆分同目录 CSS/JS。
- 更新 Open Design 根目录 `index.html` 指向物品库 v1，但不得修改或删除现有设定库产物。
- 原型必须有真实可点击交互，不能只输出说明文档或静态截图。
- 所有界面文案使用中文。
- 生成桌面 1440×900、移动 390×844 的实际渲染预览图。

## 验收标准

- 用户第一眼能区分“分类组织”“物品列表”“当前物品字段”三个层级。
- 分类字段继承关系可见但不干扰日常填写。
- 新增字段时能明确选择分类级或物品级作用域。
- 分类和字段变更不会静默删除已有值。
- 常用的搜索、筛选、新建、切换和编辑路径在 1–2 次操作内到达。
- 桌面和移动端均无溢出、遮挡和不可访问控件。
